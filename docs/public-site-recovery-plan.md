# BridgeWay Refer public-site recovery plan

Source baseline is main at `ba7e3cf` (PR #66). The production findings below come from the supplied desktop audit. Local and mobile release checks are pending for this work. The stylesheet consolidation is separate local work. If it lands first, apply the CSS tasks to the corresponding sections of `app/globals.css` and keep a single stylesheet entry point.

## Delivery order

| Change | Deliverable | Exit criteria |
| --- | --- | --- |
| 1 | Restore signup configuration and protect plan selection | Live availability responds correctly. Both entry links preserve intent, and each purchasable plan completes in Stripe test mode. |
| 2 | Replace both marketing headers with the homepage layout | Public routes share one header, with matching desktop positions and an accessible mobile menu. |
| 3 | Fix page layouts and cookie banner | The public routes pass the responsive and interaction checks below. |
| 4 | Align the offer and billing behavior | The approved billing units, Stripe checkout quantities, NFC fulfillment terms, and public copy agree. |
| 5 | Release through the existing Azure workflow | The verified revision receives traffic and production smoke checks pass. |

Confirm the offer decisions in parallel with signup diagnosis. Validate checkout pricing before enabling any production purchase path for which the billed unit and advertised unit still disagree. If configuration or approved pricing is pending for one plan, provide its explicit contact path.

## 1. Restore signup and preserve the chosen plan

1. Identify the API revision actually receiving bridgewayrefer.com traffic. Request `GET /api/signup` through the public website in a signed-out session. Capture HTTP status, `enabled`, `signedIn`, and `plans.*.available` and `amountUsd`. Repeat after sign-in to check session behavior. A successful response with `enabled: false` is the configuration branch. Network failures and non-2xx responses are the retry branch. [SignupForm.tsx](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/components/SignupForm.tsx#L22) · [Endpoints.cs](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/Endpoints.cs#L129)
2. On the traffic-serving revision, verify each predicate independently. Record pass/fail and the setting names or secret reference names. Use the deployment configuration or sanitized diagnostics for presence and key mode checks. Keep credential values out of logs, screenshots, and the plan.

   | Check | What to verify |
   | --- | --- |
   | `CustomerSignupEnabled` | Signup flag is enabled on the intended revision. |
   | `IdentityConfigured` | Tenant ID, client ID, and client secret are present. The production API checks this at startup. Also inspect Google separately because this predicate covers Microsoft. |
   | `StripeConfigured` | Stripe key is present, Workspace has a `price_` ID, and the webhook secret is configured with the expected shape. Check that the references resolve and point to the intended live account. |
   | `stripe.KeyReady` | The key is accepted by live-mode validation. Staging may explicitly allow test mode. |
   | `ManagedCallingConfigured` | Managed Calling has its own recurring Price ID. Validate that price independently even when overall signup is enabled. |

   [Settings.cs](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/Settings.cs#L27) · [StripeBillingService.cs](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/StripeBillingService.cs#L14) · [Production startup](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/Program.cs#L25) · [Provider selection](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/Program.cs#L205)

4. In `SignupForm.tsx`, remove the availability-driven Workspace assignment. Keep the URL's requested plan and render an explicit unavailable state for Managed Calling. Route Contact BridgeWay to `/contact` and let Switch to Referral Workspace explicitly select Workspace. Preserve plan intent through both provider redirects, and prevent submit while the chosen plan is unavailable. The API remains the authority for amounts and availability. 6. Exercise retries across both POSTs: signup creates or resumes the identity's workspace, then checkout starts for that workspace with the selected plan. ## 2. Share the homepage header across public routes

The audit measured the first navigation link moving 202 CSS px on Healthcare, Trades, and Pricing, and 210 px on Sign in. The root layout owns `Header`, while `LandingPage` renders separate markup and CSS hides the root header on Home. [Root layout](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/layout.tsx#L24) · [Header branches](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/components/Header.tsx#L6) · [Homepage header](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/components/LandingPage.tsx#L146) · [Visibility rules](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/landing.css#L46)

- Port the homepage's logo, link group, and account action group into the public branch of `Header.tsx`. Keep the staff/admin branches, sign-out behavior, and public intake route handling. Drive desktop and mobile from one link array in this order: How it works (`/#how-it-works`), Healthcare (`/industries/healthcare`), Trades (`/industries/trades`), Pricing (`/pricing`), FAQ (`/#faq`). Use `aria-current="page"` for the matching interior route. Keep the public signup action pointing to `/signup?plan=workspace`.
- Move the homepage header layout rules to the shared public styling section, scoped to the public header. Set one container width, inline gutter, logo size, header height, and action button sizing. Switch to mobile navigation at the first width where the full link and action groups would collide. Check this with the actual font and at browser zoom.
- Remove the duplicate homepage header markup, unused menu state and landing-only header CSS. Remove the homepage header-hide rule from both CSS locations. Keep the homepage footer visibility rule so Home has one footer. [Landing visibility](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/landing.css#L46) · [Shared header visibility](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/site.css#L23)
- Address the remaining roughly 8 px variance by testing `scrollbar-gutter: stable` on the public document scroller with classic scrollbars. Verify short and long routes and keep the root header sticky. Use one shared header offset for anchor navigation, checking direct hash loads as well as clicks. [Current scroll padding](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/globals.css#L40)
- Use a real mobile toggle button with `aria-expanded` and `aria-controls`. Closed links must leave the tab order. Close the menu after clicking a link, on route change, and when Escape is pressed. On Escape return focus to the toggle. Check the menu can scroll on short viewports and that the CTA stays reachable.

**Acceptance** Compare the bounding rectangles of the visible logo, first link, and Get started across Home, Healthcare, Trades, Pricing, and Sign in at the same desktop viewport. Each coordinate should differ by at most 1 CSS px. Repeat direct loads and back/forward with consent undecided and dismissed.

## 4. Resolve billing and physical-card wording

1. **Confirm the billed unit for both plans.** Managed Calling is presented as per location in the Pricing body and per business in other copy. Workspace advertises all locations included. Checkout starts at quantity one and currently enables customer-adjustable quantity from 1 to 50 in the shared service for both plans. Verify the actual Stripe recurring Prices and test a second location on each plan. Check every caller of `CreateCheckout`, including existing workspace Checkout. If an approved plan is per business, omit adjustable quantity for that plan and assert quantity one in a request-level test. If an approved plan is per location, document how the quantity maps to locations and verify a quantity of two bills the expected amount. Confirm how existing subscriptions are handled before changing plan behavior. [Pricing](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/pricing/page.tsx#L9) · [Checkout form fields](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/StripeBillingService.cs#L69) · [Plan price mapping](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/BridgeWay.Api/Settings.cs#L52)
2. **Confirm the physical NFC offer.** Decide whether a first set is included, what size it is if applicable, how fulfillment works, and how additional and replacement cards are billed. Confirm the staff ordering workflow and distinguish digital link and QR capabilities from physical fulfillment in the approved copy. [Home](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/components/LandingPage.tsx) · [Pricing card FAQ](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/pricing/page.tsx#L91) · [Terms](https://github.com/sampbaer-creator/Bridgewayrefer/blob/ba7e3cf/src/bridgeway-web/app/terms/page.tsx#L2)

Keep Signup's payable amounts and availability API-driven, and use the approved unit label alongside those amounts. Search hero copy, pricing metadata, features, FAQs, signup, and Terms for outdated variants. Compare final copy against the actual Stripe Checkout screen for each plan.
